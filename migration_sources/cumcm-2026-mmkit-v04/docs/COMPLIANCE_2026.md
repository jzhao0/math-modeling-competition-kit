## Paper format hard constraints

当前 2026 格式规范要求包括：
- 白色 A4 纸；上下左右页边距至少 2.5 cm。
- 纸质版：第 1 页承诺书，第 2 页编号专用页，第 3 页摘要专用页。
- 摘要含标题和关键词，原则上不超过 1 页。
- 正文从纸质版第 4 页开始；**不要目录**；正文不超过 30 页。
- 正文之后为附录，页数不限。
- 电子版论文必须是单独的 PDF 或 Word 文件，建议 PDF，大小不超过 20 MB。
- 电子版不得包含承诺书和编号专用页，因此电子版第一页必须是摘要专用页。
- 支撑材料须用 WinRAR 压缩为 RAR 或 ZIP，大小不超过 20 MB。
- 支撑材料至少应包含支撑模型、结果和结论所必要的材料，包括全部可运行源程序、自主查阅使用的数据资料（赛题提供原始数据除外）以及必要的大篇幅中间图表等。
- 支撑材料文件列表放入论文附录。
- 论文和支撑材料不得暴露参赛者身份、所在学校和赛区信息。

## AI usage

2026 AI 工具使用规定适用于大语言模型、生成式 AI、代码辅助工具和 AI Agent 等。

允许使用 AI 辅助，但：
- 核心建模与分析应主要由参赛队主导。
- 所有 AI 生成内容应逐项人工审阅和验证。
- 参赛队对原创性、真实性和准确性承担全部责任。

论文参考文献之前必须设置 **AI工具使用声明**：
- 未使用 AI：按官方指定的不使用声明填写。
- 使用 AI：按官方指定格式说明主要用途，并指向支撑材料。

使用 AI 时，支撑材料必须有：

`AI工具使用详情.pdf`

至少包括：
1. AI 工具名称、版本或模型。
2. 具体用途和使用阶段。
3. 主要提示思路和使用过程，可附典型交互示例。
4. AI 输出的主要采纳情况、人工修改和验证情况（语言润色除外）。

故意隐瞒 AI 使用、虚假声明，或把未经必要人工审阅和核验的 AI 生成内容作为核心建模和分析结果，存在取消评奖资格风险。

## Communication / GitHub discipline

2026 参赛规则明确：竞赛期间不得在任何交流平台浏览、发布或讨论与赛题相关的内容，列举的平台包括 GitHub、CSDN、知乎、小红书、贴吧、QQ群、微信群、网络直播间等。

因此本项目采取以下 hard gate：
- GitHub 参考仓库和工具资料赛前冻结到本地。
- 正式比赛开始后，不使用 GitHub 搜索赛题相关内容。
- 任何 Agent 不得通过联网搜索绕过竞赛纪律。
- 不确定是否合法的联网行为先停止，由队伍人工核对官方规则。

## Finalizer principle

自动检查只用于降低疏漏，不能替代队员对官方规则的最终确认。所有合规门禁在 G4 由三名队员人工签字/确认。

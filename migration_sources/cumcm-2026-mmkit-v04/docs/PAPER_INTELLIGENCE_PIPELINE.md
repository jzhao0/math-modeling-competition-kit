# Paper Review Bundle

This layer sits on top of the deterministic Paper Gate and Sol review packet. Its only purpose is contest-time triage: make one central Sol/human review faster without changing the selected TeX, frozen facts, model outputs, or scientific results.

## Infrastructure freeze

As of the Drill-01 review-bundle integration, this paper-review infrastructure is **feature-frozen**.

Do not add another checker, semantic layer, humanizer, review protocol, or visualization heuristic unless a later real drill shows a repeated failure that materially costs review time. A single false positive or a theoretically useful feature is not enough reason to extend the framework.

Priority from here:

1. finish the current drill;
2. run another problem end to end;
3. record repeated bottlenecks;
4. fix only bottlenecks that recur.

## Standard command

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build_paper_review_bundle.ps1 `
  -Workspace D:\Projects\CUMCM-DRILL-01 `
  -MainTex 06_paper\paper_v5_sol_revised.tex
```

The wrapper first runs the existing `build_paper.ps1 -BuildSolReviewPacket`, preserves the base Gate exit code, and then builds deterministic review material even when the Gate is `FAIL`.

## Outputs

The bundle writes only to workspace report/submission build surfaces:

- `reports/paper_intelligence.json`
- `reports/paper_intelligence.md`
- `reports/paper_visual_review.json`
- `reports/paper_visual_review.md`
- `reports/visual_review/pages/page-*.png` when `pdftoppm` is available
- augmented `reports/sol_review_packet.json`
- augmented `reports/sol_review_packet.md`

The selected TeX is protected by a before/after SHA-256 check. The bundle is read-only with respect to paper/model/data/scientific-result files.

## 1. Deterministic section/question index

`build_paper_intelligence.py` creates an index from extracted section titles and numbering. It assigns sections to `Q1`–`Q4` or `GLOBAL` using explicit title rules and, while inside a problem-analysis section, maps numbered subsections `x.1`–`x.4` to Q1–Q4.

It also tags coarse paper-function roles such as:

- `ASSUMPTIONS`
- `VARIABLES`
- `MODEL`
- `SOLUTION`
- `RESULTS`
- `ROBUSTNESS`
- `STRENGTHS_LIMITS`
- `CONCLUSION`

This is an **index**, not semantic understanding. Sol/humans remain responsible for deciding whether a section actually answers the question well.

## 2. Claim/evidence inventory and bounded triage

The script records result-like/numeric sentences, nearby explicit references, and frozen-fact hits. It distinguishes:

- `TRACEABLE_REFERENCE` — explicit reference in the same sentence;
- `TRACEABLE_LOCAL_CONTEXT` — an explicit reference in the immediately preceding sentence;
- `TRACEABLE_FROZEN_FACT` — matches an approved frozen fact;
- `NUMERIC_CLAIM_REVIEW_CANDIDATE` / `CLAIM_REVIEW_CANDIDATE` — no deterministic trace found.

The **full inventory** stays in JSON/Markdown, but the manual queue is intentionally bounded to at most four claim/evidence candidates per question. The Sol packet receives at most eight representative claims per question.

This prevents the tooling from turning every number into a new task. Missing an item from the bounded queue does not mean the claim is scientifically safe; it only means the automation chose not to spend reviewer attention on it.

A reference being present also does **not** prove that the evidence is sufficient or correct.

## 3. Frozen facts

The repository-level `config/paper_facts.yaml` is a generic store and may legitimately be empty before a drill has approved problem-specific facts.

For real contest/drill use, pass a problem-specific facts config once those facts have been human/Sol approved. Do not populate the generic repository file with one problem's numbers merely to make the intelligence report look complete.

An empty facts file is therefore not a Gate error; it only means `TRACEABLE_FROZEN_FACT` cannot be used for that run.

## 4. PDF visual review

`paper_visual_review.py` consumes the Poppler bbox output already generated by the Paper Gate and optionally renders each PDF page to PNG using `pdftoppm`.

Geometry heuristics currently cover:

- very sparse pages;
- unusually dense pages;
- content near a page edge;
- very small rendered images;
- oversized rendered images.

The page PNGs are primarily for Sol/human visual inspection. Geometry findings are grouped by warning code before they enter the Sol manual-review queue, so ten pages with the same heuristic do not create ten separate review tasks.

The automation does not judge chart semantics, typography aesthetics, color quality, scientific adequacy, or whether a figure deserves to remain in the paper.

## 5. Sol packet augmentation

`augment_sol_review_packet.py` enriches the existing fixed `0`–`15` packet; it does not create a competing review protocol.

It adds:

- the deterministic section/question index;
- bounded representative Q1–Q4 claims;
- the bounded claim/evidence triage queue;
- grouped visual findings;
- a page-level visual summary;
- full machine-readable intelligence in the JSON companion.

The augmented queue is **review guidance, not a checklist to clear**. Do not rewrite a correct paper merely to eliminate intelligence or visual-review warnings.

## Contest-time division of responsibility

**Programmatic Gate** handles hard, deterministic failures such as compilation, fact drift, broken references, internal-token leakage, and layout errors that have reliable rules.

**Review bundle** reduces navigation and triage cost.

**Sol/human review** decides scientific correctness, modeling choice, evidence sufficiency, natural Chinese writing, interpretation, figure quality, and whether a warning is worth acting on.

After the current drill, do not tune this layer again until another real drill demonstrates a repeated, high-impact gap.
